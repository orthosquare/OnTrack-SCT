Sidebar support is provided through the Astro/Starlight sidebar library. This
can be maintained manually or elicited by the autosidebar. Even though the
documentation provided by starlight is very well written, a small guide to 
using the sidebar will be added here for completeness.

## Manual sidebar entries

We add manual sidebar entries to by adding entries to the list of sidebar
elements in `astro.config.mjs` to pages in `src/content/docs/`. An example
of this current website, using manual sidebar entries, is given below:

```
sidebar: [
    {
        label: 'Welcome',
        items: [
            { slug: 'welcome/foreword' }, 
            { label: 'Markdown', 
                items: [
                    { slug: 'welcome/markdown/structure' },
                    { slug: 'welcome/markdown/markdown' },
                    { slug: 'welcome/markdown/extensions' },
                    { slug: 'welcome/markdown/sidebars' },
                ],
            },
        ],
    },
],
```

Note that this gives full control over the sidebar to the config file and any
sidebar layout rules defined in the frontmatter will be ignored.

You can also include links to external sources using the link key, as opposed
to the slug key:

```
sidebar: [
    { label: 'NASA', link: 'https://www.nasa.gov/' },
],
```

Enteries can be added to the sidebar at any level, including the root level.

## Auto Sidebar

Auto sidebar uses the directory structure, frontmatter, and `_meta.yml` files
to automatically generate a sidebar. For example, we can generate our current
sidebar with:

```
sidebar:[
    {
        label: 'Welcome',
        items: [{ autogenerate: { directory: 'welcome' } },],
    },
],
```

This call to autogenerate only acts on the directory give, this means that you
can mix autogenerate calls with manual entries. Allowing for greater control.

### Using metadata

To enable formatting and ordering of sections that are autogenerated from out
folders, we are able to specify frontmatter for the directories using the
`_meta.yml` files. An example of the  `markdown/_meta.yml` file is given blow.
Note that we are able to order the folders relative to each other and other
pages that exist at the same level.

import { Code } from '@astrojs/starlight/components';
import sample_meta from '/src/content/docs/welcome/markdown/_meta.yml?raw';

<Code code={sample_meta} title="markdown/_meta.yml" />

Importantly, pages use the `title` key where as folders use the `label` key.
